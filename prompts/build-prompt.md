# פרומפט לבנייה ב-Claude Code

## הכנה (פעם אחת)
1. לשכפל את הריפו: git clone https://github.com/Anat1969/Dapar-GH.git
2. להיכנס לתיקייה ולפתוח את Claude Code בתוכה.
3. להריץ בטרמינל: uipro init --ai claude

## הפרומפט להעתקה

קרא לפני כל דבר את CLAUDE.md, README.md, ואת כל הקבצים בתיקייה docs/. הם מגדירים את המוצר, את מודל השליטה בשלוש שכבות, את התוכנית היומית ואת המסכים. אל תתחיל לכתוב קוד לפני שסיימת לקרוא.

עבוד לפי הסקיל end-to-end-builder. אל תעצור לשאלות שאפשר להכריע לבד. כשיש החלטה, בחר, ציין את ההנחה בשורה אחת, והמשך.

המטרה: אפליקציית PWA בעברית (RTL) לתרגול דפ"ר, עם Supabase, לעילאי ולאדמינית (ענת).

שלבים לביצוע, לפי הסדר. אחרי כל שלב: הרץ בדיקות, קומיט לענף, ותאר במשפט אחד מה נבנה.

שלב 1: פרויקט Vite + React + TypeScript. התקן Tailwind, Vitest, Playwright. הגדר RTL ברמת html (lang="he" dir="rtl"). צור את src/config/app.ts (יעד ציון 90, ספי מעבר לפי docs/02) ואת src/config/links.ts (הקישורים TBD, כפי שמוגדר ב-CLAUDE.md).

שלב 2: מנוע הלוגיקה בתיקייה src/engine, כפונקציות טהורות עם בדיקות Vitest:
- mastery.ts: האם פותחים שכבה, האם נותקעים, האם חוזרים שכבה אחורה.
- errors.ts: ספירת טעויות חוזרות לפי (נושא, סוג). במופע השלישי מחזיר דרישה לניסוח.
- score.ts: ציון משוער פנימי לפי פרקים. מסומן בבירור כמדד פנימי.
- plan.ts: תוכנית היום לפי docs/03, כולל תאריך נוכחי והיום בתוכנית.
כתוב בדיקות לכל כלל מ-docs/02.

שלב 3: Supabase. הרץ את supabase/migrations/0001_init.sql בפרויקט שאציין לך (או צור פרויקט חדש אם אין). ודא ש-RLS פעיל בכל טבלה, ושה-policies תואמות את docs/04. אל תכניס מפתחות סודיים לקוד.

שלב 4: אימות. כניסה עם Google דרך Supabase Auth. אם Google כבוי, הצג הודעה ברורה. הגן על כל המסכים מלבד הכניסה.

שלב 5: מסכים לפי docs/05, בסדר: היום, תיקון טעויות, תרגול לפי שכבה, מבחן מדומה (חלקי ומלא עם טיימר), דוח מבחן, לוח מדידה, ניהול בנק (אדמין בלבד).
- סרגל עליון קבוע בכל הדפים, כולל דיאלוגים שנפתחים מתחתיו.
- שם האפליקציה הוא קישור לדף הבית.
- כפתורים: "העתקת קישור", "שיחת הפיתוח", "פרויקט המחקר", "התקנת האפליקציה" (מוצג רק כשניתן להתקין).
- בלי אייקונים. טקסט בלבד.
- מצבי טעינה, ריק, שגיאה, ואין הרשאה לכל מסך נתונים.
- הרשומות נשמרות מיד, ושאלה לא מאבדת תשובה אם המשתמש יוצא מהדף.

שלב 6: PWA. manifest.webmanifest בעברית עם dir rtl ו-lang he, display standalone. אייקון בלי טקסט. sw.js שמטמן נכסים סטטיים, בלי לשמור תשובות Supabase. כפתור ההתקנה מופיע רק כש-beforeinstallprompt נשלח.

שלב 7: בדיקות. Vitest לכל src/engine. Playwright smoke: לחיצה על כל כפתור בסרגל, כניסה למסכים, הפעלת תרגול, הפעלת מבחן מדומה. ודא שאין גלילה אופקית בנייד (רוחב 380). צלם מסכים וסקור אותם.

שלב 8: GitHub ו-Vercel. פתח PR לכל שלב גדול. אחרי בדיקה ירוקה, מזג ל-main בלי לשאול. פרוס ב-Vercel מ-main, בלי teamId, עם ssoProtection: null. ודא שהפריסה READY, ושהנתונים הציבוריים חוזרים מ-Supabase.

כללים שאסור להפר:
- עברית בלבד בממשק. בלי אייקונים.
- שלוש שכבות לכל שאלה. אסור לפתוח יישום לפני ידע והבנה.
- כל טעות נרשמת עם סוג. טעות חוזרת שלוש פעמים: עצירה וניסוח במילים של עילאי.
- ציון משוער תמיד מסומן "מדד פנימי, לא ציון רשמי".
- שאלה מסומנת official או reconstructed רק אם המקור מוגדר. אסור להמציא שאלות רשמיות.
- אין מפתחות סודיים בקוד, ואין נתונים רפואיים או רגשיים.

מסירה: כתובת סופית של Vercel, ושורה אחת על מה נבנה. כל תיקון שאני מבקשת נכנס ל-CLAUDE.md בסעיף "תיקונים שנלמדו".
